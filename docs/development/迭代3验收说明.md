### 主要改动一览

- **AI 服务**（新目录 `service-fastapi/`，独立 `pyproject.toml` + `uv.lock`，Python 3.14）
  - lifespan 复用 HTTP 客户端、认证 Redis 与模型并发信号量；DRF 上下文与模型提供方各用独立连接池。
  - `get_current_user`：固定 `HS256`、`aud=x`、`iss=server`、`exp`/`iat`/`jti`/`user_id`/`token_type=access`，leeway 0；
    一次 `MGET` 读 `black_access_token_*`、`user_token_revoked_*`、`session_token_revoked_*`（值格式按 django-redis 整数直写，
    已用 DRF 实签 token 交叉验证）；认证 Redis 故障 503。
  - `POST /ai/v1/tickets/analyze`：每次（含缓存命中）经 DRF `ai-context` 确认授权；Pydantic v2 校验分类在当前词表、优先级 P0–P3、
    摘要与标签上限；缓存键绑定用户、规范化文本摘要、词表、模型与提示词版本，TTL 600 秒，只缓存合法结果。
  - `POST /ai/v1/tickets/suggest-reply/stream`：SSE `meta` → `delta`* → `done`，建流后失败以 `error` 结束，空闲发 `ping`；
    客户端断开即关闭上游并释放信号量；首段正文前允许重试一次。
  - 错误信封 `{code, error, detail}`（`code` 为 HTTP 状态码整数）。Mock 与 OpenAI 兼容提供方共用同一控制面。
  - 多阶段非 root 镜像；根目录新增 `.github/workflows/service-fastapi.yml`（只在服务目录变化时触发）。
  - 82 个服务测试（真实 Redis），含断开释放信号量、槽位占满时缓存命中与 403 不受影响。
- **前端**（`frontend/`）
  - `ReHumanCheck` 组件与 `utils/captcha`：出题 → HMAC 签名校验 → 一次性 ticket，静默 PoW、图片、滑块三种题型，
    签名与摘要用后端函数算出的向量做单测；登录、发码、邀请激活接入；携带票据的请求附 `X-Captcha-Fp`。
  - 工单详情右侧 AI 面板（仅 `viewer.can_handle`）：分析与一键采纳、流式回复建议；流 401 交给既有会话处理后重试一次；
    换工单、关闭抽屉、重新生成都会取消在途流。开发代理 `/ai/` → `:8897`。
  - 新增前端单测 52 条（人机校验 30 条、AI 面板 22 条）。
