# 迭代 6 角色改造方案

本文记录 2026-11-23 与用户讨论确定的角色、权限和新功能口径，是迭代 6 后续任务书的依据。
接口细节以各任务书和 `backend-drf/docs/schema/` 为准；本文未提及的行为沿用
[Phase 1 设计评审](../../backend-drf/docs/plans/ticketflow-phase-1.md)。

## 1. 三个角色

| 角色 | 角色编码（沿用） | 演示账号 |
| --- | --- | --- |
| 普通员工 | `ticketflow_requester` | `tf_requester` |
| 技术员 | `ticketflow_agent` | `tf_agent`（工单支持组）、`tf_agent_other`（网络支持组） |
| 管理员 | `ticketflow_admin` | `tf_admin` |

- 角色编码保持不变，只改显示名，避免牵动权限点、种子和测试。
- 知识维护角色 `ticketflow_kb_editor` 并入管理员后下线：已有授权迁移到管理员，种子与代码中删除该角色。
- 超级管理员 `admin` 保留，负责底座的系统配置（菜单、权限点、站点设置），不参与业务。
- 登录页关闭自助注册，账号由管理员创建。

## 2. 技能组

- 现有“部门”在业务上改称**技能组**（如工单支持、网络支持），底层仍是 `DeptInfo`，接口字段不改名，界面文案改为技能组。
- 技术员归属一个技能组；员工不需要技能组。
- 建单时按分类路由到技能组的规则不变（无配置时走默认支持组）。

## 3. 可见范围与动作

| 能力 | 普通员工 | 技术员 | 管理员 |
| --- | --- | --- | --- |
| 看到的工单 | 本人提交的 | 当前指派给自己的（可操作）+ 曾经指派给自己的（只读）+ 本人提交的 | 全部，含“待分配” |
| 建单 | ✓ | ✓（以提交人身份） | ✓ |
| 接单、对外回复、内部备注、提交验收 | — | 当前处理人 | ✓ |
| 退回重派（填原因） | — | 当前处理人 | — |
| 指派 / 改派 | — | — | ✓ |
| 验收确认、验收退回、重新打开 | 本人提交的 | 本人提交的 | ✓ |
| 评价工单与处理人 | 本人提交且已关闭的 | — | — |
| 看评价 | 自己给出的 | 自己处理的工单收到的 + 个人汇总 | 全部 + 按技术员统计 |
| AI 知识问答 | ✓ | — | 只看反馈页 |
| 工单详情里的 AI 面板（分析、回复建议） | — | 当前处理人 | ✓ |
| 知识库 | 浏览已发布 | 浏览已发布；把自己经手的已关闭工单转存为草稿 | 全部：编辑、审核、发布、归档 |
| 账号与技能组管理 | — | — | 业务账号 |
| 导出 | — | — | ✓ |

说明：

- **经手过就算历史**：工单改派后，原处理人仍能在历史里看到这张单和自己当时的处理记录，但不能再操作；
  后续由新处理人负责。需要一张指派历史表记录每段指派的起止时间和原因。
- 只读的历史工单对原处理人展示完整时间线（含内部备注），但不显示任何操作入口，也不能调用该工单的 AI 面板。
- 不提供技术员之间直接转派，统一走“退回 → 管理员重派”，便于管理员掌握分配情况。

## 4. 自动派单

- 建单后在同一事务内自动指派：取工单所属技能组里**在职、启用**的技术员，选未完成工单
  （非 `CLOSED`）最少的一位；并列时选最近一次被指派时间最早的，再按用户名排序，结果确定。
- 技能组里没有可用技术员时，工单保持未指派，进入管理员的“待分配”视图。
- 技术员退回：清空处理人，记录原因和日志，工单进入“待分配”，状态不变；管理员改派时可以看到退回原因。
- 重新打开：优先回到上一位处理人（仍是该组在职技术员时），否则重新自动派单。
- 自动派单、改派、退回都写工单日志和指派历史，自动派单的操作人记为系统。

## 5. 工单评价

- 时机：员工确认解决、工单关闭时弹出评价，可以跳过，之后在工单详情里补评。
- 每张工单只评价一次，提交后不可修改；技术员不能回复评价。工单重开再关闭不产生第二次评价。
- 内容：
  - 处理结果：问题是否解决（是 / 否）、满意度 1~5 星；
  - 处理人：评分 1~5 星，可选标签（响应快、专业、态度好、沟通清楚等，固定词表），文字评价（可选，长度上限）。
- 评价绑定关闭时的处理人。
- 技术员“我的评价”：平均分、评价数、解决率、最近评价列表；管理员“评价统计”：按技术员汇总并可下钻到评价明细。

## 6. 员工 AI 知识问答

- 入口：员工菜单“AI 助手”，首页工作台加快捷入口。
- 会话：保存在系统里，左侧是本人的历史会话列表，可继续追问、可删除（软删除）。
- 回答：只依据**已发布**的知识文章，检索不到时明确说明并建议转人工；流式输出，附引用文章，点击打开原文。
- 评价：每条回答可点赞或点踩；点踩可选原因（不准确、没解决、引用不相关、其他）并写一句补充。
- 转人工：员工点“转人工提单”，AI 把对话整理成标题、问题描述和建议分类，预填新建工单表单，员工确认后提交；
  工单关联这段会话，处理人在工单详情里可以查看。
- 管理员“AI 反馈”页：只看被点踩的回答（含上下文）和转人工的会话，用来补充知识库；其他对话只看统计
  （问答量、好评率、转人工率）。
- 架构沿用现有分工：会话、消息、反馈存在 DRF；FastAPI 负责检索上下文后流式生成和转人工摘要，
  通过内网接口向 DRF 读取上下文、写回回答；鉴权、撤销、限流、并发控制与现有 AI 接口一致。

## 7. 账号与技能组管理（管理员）

- TicketFlow 下新增“账号管理”页，使用专用接口，不复用底座的系统用户管理：
  - 新建、编辑、停用业务账号（用户名、姓名、联系方式、角色三选一、技术员的技能组），重置密码；
  - 只能管理三种业务角色的账号，不能设置超级管理员、不能分配其他角色、不能修改超级管理员和自己的角色。
- “技能组管理”：新建、改名、停用技能组，设置分类到技能组的路由。
- 账号停用后不再参与自动派单；名下未完成工单进入“待分配”。

## 8. 菜单

| 角色 | 菜单 |
| --- | --- |
| 普通员工 | 首页、我的工单、AI 助手、知识库 |
| 技术员 | 首页、我的工单（处理中 / 历史）、我的评价、知识库 |
| 管理员 | 首页、全部工单（含待分配）、知识库、评价统计、AI 反馈、账号管理、技能组、导出中心 |

首页工作台按角色调整计数卡与快捷入口（员工突出“新建工单 / AI 助手”，技术员突出待处理，管理员突出待分配与 SLA）。
