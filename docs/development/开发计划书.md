## 1. 项目目标

TicketFlow AI 是基于 xadmin（xadmin-server + xadmin-client）二次开发的企业级智能工单与知识库协作平台。交付目标：

1. **工单协作**：建单（幂等）、按分类路由部门、指派、状态流转（并发版本控制）、对外回复与内部备注、SLA 预警与超时告警、看板与异步导出。
2. **知识库**：文章草稿、审阅发布、归档，从已关闭工单转存，检索已发布文章片段供 AI 引用。
3. **AI 辅助**：独立的 FastAPI 异步服务，复用 DRF 的 JWT 与撤销状态，对工单做分类/优先级/摘要分析，流式生成回复建议（SSE）。
4. **工程质量**：真实 PostgreSQL + Redis 下的测试、CI 门禁、统一网关部署、压测数据，可作为面试复盘材料。

## 6. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 前端底座落后后端 HEAD | 隐藏的接口不一致在联调时才暴露 | FE-06 全量比对；必要时从上游 xadmin-client 同步对应模块 |
| 本地时钟回跳 | 并发测试偶发 401 | 以 GitHub CI 为准；本地复核采用串行重跑 |
| 守护测试快照写死计数 | 新增模块或菜单需同步更新 | 评审时检查快照更新理由；后续把可推导的计数改回动态计算 |
| AI 真实模型的成本与延迟 | 压测与演示不稳定 | Mock 与真实提供方共用同一控制面，压测固定使用 Mock |
| fork 仓库的 Actions 限制 | 推送不触发 CI | 已由用户启用；合并后确认推送自动触发，必要时手动触发 |
